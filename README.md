# InsightGrid

运营商政企客户经理的商机工作台：每天跟上放标，看清交付内容，并提前对接续约和生态。

本仓库是 Apache-2.0 开源空壳。规划已定，应用还不能运行。采集实现、真实客户数据和提示词不在这里。

## 聚焦

InsightGrid 做**战略客户的商机经营**，不做招标搜索引擎。

从救火式盯网站，变成跟得上、读得懂、续约能提前对接。部门以后若要用，用的也是这套判断，不是又一个爬虫。

和能力匹配：你懂客户、口径、生态和合规；养采集器和大平台会拖死你。采集用 PAD 即可替换，该沉淀的是字段和判断。

只盯三件事：

1. **在跟客户的标讯** — 按客户及时看到该响应的标
2. **交付内容** — 简章里要什么、自有能力或生态能不能做
3. **续约和生态** — 对接在跟客户、原中标方，还是其他厂商

先放下：通用标讯搜索、关系图谱、部门大平台、开源采集器。

## 要解决的问题

客户经理太忙，没有时间每天盯招标网站，无法及时响应标讯。对已有客户的商机范围没有概念，不知道能往哪个方向合作，也不会为历史中标后的续约早做打算，更不会提前联络相关生态。

普通标讯工具只回答「最近有哪些公告」。InsightGrid 要回答：

1. **今天放了哪些标** — 按已关注客户汇总，便于及时响应
2. **标里要交付什么** — 分析招标简章中的项目交付内容
3. **续约和合作该提前对接谁** — 客户已经在跟，不是去「找客户」。要判断的是：该提前和在跟客户谈采购窗口，联络原中标方能否联合，还是引入其他生态厂商

## 版本

| 版本 | 做什么 | 状态 |
| --- | --- | --- |
| v0.1 | 按客户汇总结讯；数据字段可定制；浏览器表格 + 导出 CSV，供外部智能表格分析 | 规划中 |
| v0.2 | AI 分析招标简章中的交付内容（基于网页获取的数据） | 未开始 |
| v0.3 | 查该站历史中标，分析周期性项目、历史采购内容和历史中标方 | 未开始 |

v0.1 不做简章正文分析、历史中标和续约推断，也不做关系图谱、数据看板和商机评分。不自动登录抓取需登录的正文。

## 谁在用

先做个人工具，再做成部门平台。对外只开框架、说明和脱敏示例。

## v0.1 怎么用

1. 维护关注客户
2. 按自己的跟进习惯定制数据字段（列名、是否导出）
3. 工作日读取来源网站的公开列表
4. 按客户把新标汇总到浏览器表格
5. 需要时导出 CSV，用 Excel、WPS 或其他智能表格继续分析
6. 看正文时打开原始链接

来源网站的正文和附件常常要登录。v0.1 不代你登录，也不保存账号或 Cookie。

## 技术栈

Vue 3、FastAPI、PostgreSQL、Docker Compose、APScheduler。Kimi（Moonshot）从 v0.2 起用于简章分析。

不用 Elasticsearch、图数据库、Redis、向量库和 Kubernetes。

开发和测试先在 macOS 上，随后在 Windows 11 上；两台机器都在 Docker Desktop 里运行，不在宿主机直接装数据库或运行时。

安装和运行说明将在 v0.1 可运行后补充。请先安装 Docker Desktop，用同一套 `docker compose` 在 Mac 和 Windows 上启动。

## 数据与合规

只使用合法、公开或已获授权的数据，并遵守来源网站规则和本单位安全要求。

本仓库不放真实客户数据、账号、Cookie、Token、私钥，以及内部接口和业务规则。采集不绕过登录墙。

公开数据记录来源和获取时间。跟进记录留在本地，不进 GitHub。
