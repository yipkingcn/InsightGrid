来源：你整理的《南网供应链放标抓取 v3 —— 架构逻辑与学习地图》（2026-09-19，118 条动作，实机 0 错误）。本文只沉淀**迁到 InsightGrid 时要留下的东西**。PAD 特有变通不进产品。

状态：探路有效。正式代码未开工。不进 GitHub，除非你确认。

## 已经证明的事

定时增量抓取可以跑通：按单位关键词翻页、按公告 ID 去重、CSV 落盘、漏跑能靠日期扩窗补抓。这就是最小需求的采集骨架。

InsightGrid 以后要继承的是这套**判断规则**，不是 118 条 PAD 动作。

## 必须留下的不变量

迁到 Python / Docker 时这些必须恒成立：

1. 同一输入连跑两次，产出文件内容一致（幂等）
2. 主表只追加；增量快照和 `lastrun` 只覆盖；运行日志和错误日志只追加
3. 只有「完整跑完且无积压」才更新 `lastrun`
4. 任何异常必须留痕，禁止裸 `except`
5. 关浏览器 / 关连接必须在 `finally`，出错也要回收

## 必须分开的两条退出路径

| 情况 | 含义 | 状态 |
| --- | --- | --- |
| 本页候选全部已见 | 抓完了 | 可更新 lastrun（若无积压） |
| 翻到页数上限仍有未见 | 抓不动了，有积压 | **不**更新 lastrun，次日补抓 |

不要把「没有新公告」和「页数到顶」合成一个布尔。合成之后积压会静默丢数据。这是 PAD 阶段最贵的一课。

## 三态

- `FIRST_RUN`：该单位还没有主表 → 回看建库页数（覆盖长假）
- `NORMAL`：有主表、缺口在上限内
- `BACKLOG`：翻到日常页数上限仍有未抓

不要预创建主表 CSV。预创建会让首跑被当成日常，早期公告永远抓不到。试跑成功后若要正式建库，先删主表和 `lastrun.txt`。

## 迁到代码时丢掉的 PAD 写法

| PAD 变通 | 代码里该怎么做 |
| --- | --- |
| 长文本模拟已见集合 | 原生 `set`，从主表 ID 列重建 |
| `RunOK` 哨兵 + 块中错误 | `try / except / finally` |
| 按动作编号定位 | 按模块：state / crawl / parse / store |
| 固定等待秒数 | 等页面出现「采购公告」这类条件 |

## 建议的代码切片（以后才做）
