# 当前数据标准（PAD → 智能表格）

你 2026-09-19 确认的最小字段。InsightGrid v0.1 对齐这一套，不提前扩列。

## 现在用的列

| 列 | 用途 | 备注 |
| --- | --- | --- |
| 公告 ID | 去重主键 | 跨运行从主表重建已见集合 |
| 招标人/采购人 | 按客户汇总 | 对应关注单位关键词 |
| 项目名称 | 表格主读字段 | 及时响应看这一列 |
| 公告类型 | 筛选 | 招标 / 采购等 |
| 公告日期 | 排序、补抓窗口 | |
| 详情链接 | 打开原文；后期喂 LLM | 取 href，不要取链接文字 |
| 首次抓取时间 | 审计 | 只在首次入库时写，追加主表后不再改 |

可定制：智能表格里可以加计算列或隐藏列；采集侧这 7 列先锁。导出 CSV 与这 7 列一致。

## 后期（v0.2）：详情页正文 + LLM 格式化

详情页结构不稳定，定向抓字段 / 抓包效果不好。计划：用详情链接取**主体文本**，交给 Kimi 做成固定结构（先交付内容，再及其他）。

约束：

- 只处理能合法打开的页面（公开或本人已登录后可见）
- 不绕过登录墙，不保存 Cookie / 账号，不把抓包证书方案写进产品
- 列表这 7 列仍是主表；LLM 产出另表或另列，失败不影响公告入库
- 提示词不进 GitHub
